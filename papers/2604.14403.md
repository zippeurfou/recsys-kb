## Summary

Traditional RAG systems require server-side processing, leading to privacy issues, costs, latency, and internet dependency. On-device RAG avoids these but faces challenges with limited device memory and disk space needed for context and embeddings. This paper proposes a unified model that compresses the RAG context and uses the same compact representations for both retrieval and generation, significantly reducing storage needs while maintaining performance.

## Technical note

The ECG (Embed, Compress, Generate) model runs the full RAG pipeline on-device by using a single model and a single set of vectors for retrieval, context compression, and generation. Documents are compressed offline into a small number of embeddings that double as the retrieval index (searched via MaxSim, late-interaction style), eliminating separate retrieval and compression representations and roughly halving preprocessing compute, disk, and memory. It matches a standard RAG reader with about 1/10 the context and up to 16x document-representation compression, while using slightly less disk than a multi-vector retriever. The work targets privacy, offline availability, and storage constraints of querying personal documents locally.
