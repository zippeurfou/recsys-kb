## Summary

This paper introduces GRACE, a system designed to deploy generative recommenders for real-time ad retrieval in production environments. It tackles two main challenges: ensuring each generated ad candidate meets advertiser eligibility rules (generative target matching) and optimizing the compute cost and latency of generating many ads quickly.

GRACE addresses the eligibility issue with Generative Target Matching (GTM), leveraging bitmask/Bloom filter matchers on Semantic IDs derived from targeting rules, significantly improving final ad-level filtering pass rates compared to standard methods alone. For computational efficiency, it focuses on lightweight encoder-decoder Transformers suitable for wide-beam decoding and implements specific optimizations.

Furthermore, GRACE optimizes the decoder by redesigning attention kernels (both self- and cross-attention) and beam search processes for short sequences and wide-beaming, resulting in substantial latency improvements (over 20x faster than baselines) on NVIDIA GH200 hardware. These combined innovations allow generative ad retrieval to meet strict performance requirements effectively.

## Technical note

Serving SID-based generative retrieval for ads breaks on two axes: advertiser audience-targeting rules make eligibility request-specific (catalog-valid constrained decoding is not enough), and the wide-beam short-sequence decoder shape leaves general attention kernels badly underutilized. GRACE (Meta) adds Generative Target Matching, which augments the GPU trie used for catalog-valid constrained decoding with per-prefix bitmask matchers for low-cardinality attributes (country, age, gender) and Bloom-filter matchers for high-cardinality ones (fine-grained location), masking any next token whose prefix retains no eligible ad; over a 30M-SID index this lifts the final exact ad-level target-matching pass rate from 23.55% to 40.42% (20.83% to 56.33% in the <5k-generated-ads bucket), while k-way matcher partitioning lowers fill rate without improving final pass rate. For compute it targets a 3-layer encoder-decoder (16 heads, d_h=128, |V|=512, L_SID=4, 128 InterFormer-style context tokens) and rewrites the decoder: a beam-as-query cross-attention layout cuts cross-attention from 9.6 ms (FlashAttention-2) / 6.9 ms (FA3) to ~0.1 ms (98.5x / 68.0x); a coalesced short-sequence Triton self-attention kernel plus a paged block-table KV cache cuts self-attention from 5.5-6.0 ms to 0.216-0.238 ms per step (23.4-25.8x, HBM utilization 2.38% -> 84.46%); and dynamic per-step beams (1,512,1024,1024) cut FLOPs from 0.533 to 0.446 TFLOPs/request (-16.2%). Decoder P50 falls 11.1x from 197.7 ms to 17.8 ms (15.5 ms with dynamic beams), and with both GTM matchers enabled full-model P99 is 53.6 ms on a GH200, inside the ~70 ms compute window of a P99 <100 ms budget, at 28.8% decoder MFU.
