## Summary

1.  Standard sequential recommendation methods use the same embedding for all users for each item, ignoring individual user context. The paper proposes an alternative called PRISM where item embeddings are personalized based on a user's specific history.
2.  PRISM achieves this personalization by employing an autoencoder that compresses relevant information from upstream ranking models and different tower representations (user, user-item, candidate mixing) into unique embeddings for each item a user interacts with.
3.  Offline evaluation shows PRISM improves downstream recommendation performance slightly ($-0.15\%$ normalized entropy) compared to standard methods, especially noticeable with longer user histories following a power-law scaling relationship.

## Technical note

Sequential recommenders (SASRec, HSTU, OneTrans) embed each history item with a user-independent map, so the same item looks identical for a casual viewer and a creator. PRISM (Meta) makes personalization a property of the history inputs: an upstream ranker with a user tower, a user-item pair tower (multitask engagement heads) and a same-request candidate-mixing Transformer (item plus request-level aggregate heads over stop-gradient pair states) has the hidden states of every layer RMS-normalized, concatenated and compressed by a detached autoencoder (softsign-bounded encoder, MSE reconstruction) into one 128-d INT8 code per scored user-item event; codes are exported with timestamps and replayed chronologically (latest 400 events within 30 days, mean length 235) as tokens that a downstream ranker reads with candidate-conditioned attention alongside its ordinary features. On Meta's billion-scale Surface 1 (3 training days, 30-50B examples), adding PRISM history changes average NE by -0.15% (positive tasks -0.17%, negative -0.11%; like -0.22%, comment -0.20%) versus -0.07% for VISTA's cached history summary tokens at similar lengths, where 0.03% NE is significant. Sweeping 26 to 240 retained events, NE gain follows a power law g(L) ~ 0.0131 L^0.468 (0.06% to 0.17%), so doubling history yields about 1.38x the gain, framing personalized history length as a new scaling dimension.
