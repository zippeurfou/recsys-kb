## Summary

This paper introduces **JIR-Arena**, a new multimodal benchmark dataset specifically designed for Just-in-time Information Recommendation (**Just-in-Time IR**) systems. It provides the first formal mathematical definition of JIR tasks and proposes associated evaluation metrics to assess them across dimensions like accurate need inference, timely recommendations, and avoidance of distractions.

The development of **JIR-Arena** addresses key challenges in evaluating always-on intelligent assistants capable of delivering real-time information: the subjectivity of user needs estimation and the difficulty in controlling system variables. The dataset combines human inputs with AI model outputs to approximate information need distributions and employs a multi-turn validation framework for improved objectivity.

Finally, the authors implement a baseline JIR system using foundation models and evaluate it on their own dataset (**JIR-Arena**), finding reasonable precision but challenges regarding recall and effective content retrieval. They fully release both **JIR-Arena** data/code and the base system to support further research in this emerging field of JIR development.

## Technical note

There was no formal task definition, benchmark, or evaluation framework for Just-in-time Information Recommendation (JIR), where an always-on assistant proactively delivers relevant info at the right moment. The paper formalizes JIR as a POMDP and introduces JIR-Arena, the first multimodal benchmark (34 scenes, 831 minutes of lectures/talks) that approximates the user information-need distribution by combining multiple humans and large foundation models with multi-turn, multi-entity voting, and scores instances against static Wikipedia/arXiv/textbook knowledge bases. It defines Recall, Precision, R_relevance (nDCG-based), and R_timeliness (Gaussian-kernel) metrics, and implements a baseline system pairing generative LLMs (gpt-4o, DeepSeek-V3, claude-3-7, gemini-2.0-flash) with BM25/OpenSearch retrieval. Baselines achieve reasonable precision (~0.69) but low recall (~0.33-0.43) and very poor R_relevance (~0.015), showing content retrieval is the key bottleneck.
