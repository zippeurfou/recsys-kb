## Summary

Current visual-language models struggle with the inconsistencies and heterogeneity found in real-world documents, causing problems in cross-modal retrieval. To address this, the authors introduce Evo-Retriever, a novel framework using an LLM as a meta-controller. Evo-Retriever enhances multimodal alignment through multi-view image alignment and bidirectional contrastive learning, then uses the LLM to adaptively adjust the training curriculum based on the model's evolving state, achieving state-of-the-art results.

## Technical note

Evo-Retriever is a complex visual document retrieval framework in which the model and its training curriculum co-evolve, built on late-interaction multi-vector representations (ColPali-style, OCR-free VLM backbone). Multi-view Image Alignment (MVA) constructs rotated, scaled, and stitched views processed by a shared encoder and aligned to text via a consistency loss to improve spatial awareness over fragmented layouts. Bidirectional Contrastive Learning (BCL) adds a reverse document-to-query path that synthesizes textually similar but visually distinct hard-negative queries to counter textual confusion. Over this Viewpoint-Pathway collaboration, an LLM meta-controller (LLM-guided Evolutionary Curriculum) reads training-state summaries such as loss dynamics and historical decision performance to adaptively adjust hard-negative difficulty as the model converges, avoiding stagnation from a static curriculum. It reaches nDCG@5 of 65.2% on ViDoRe V2 and 77.1% on MMEB (VisDoc).

- Effective Learning Window ($[0.3,1.2]$): This is the empirically determined ideal range for the loss. For the softplus-based contrastive loss with a temperature of $\tau=0.02$, a loss below 0.3 heuristically indicates that negatives are too easy, providing insufficient learning signal. A loss above 1.2 suggests a risk of training instability, where the model struggles to converge. This window filters for actions that are both challenging and stable
- Trend Estimation Window (20%):
- Anchor Point Principle (Difficulty-Optimized Selection):
- Action ($a$): An integer index from 0 to 15, corresponding to a predefined difficulty interval (see [Tab.˜5](#S7.T5)). In logs, these may be represented by letters “A” through “P”
- Hard Negative Loss ($\mathcal{L}_{\text{neg}}$): The primary real-time performance metric for decision-making. It is the mean value of the total contrastive loss, $\mathcal{L}_{total}$ (Eq. [1](#S3.E1)), computed within a review window. This loss directly reflects the model’s performance on the current curriculum’s hard negatives. For historical records, this value is stored as avg_loss
- Historical Summary ($H$): A record of all previously executed actions. Each entry contains at least the action taken and its resulting average loss, i.e., a tuple of (action, avg_loss), along with metadata such as the global step. This summary serves as the historical context for the overall decision-making process
- High-Loss Anomaly: If $\mathcal{L}_{\text{neg}}>1.2$, difficulty is reduced by 2 intervals ($a_{\text{next}}\leftarrow\max(a_{\text{current}}-2,0)$)
- Low-Loss Anomaly: If $\mathcal{L}_{\text{neg}}<0.05$ for two consecutive reviews, difficulty is increased by 3 intervals ($a_{\text{next}}\leftarrow\min(a_{\text{current}}+3,15)$)
- Default Progression: Otherwise, select the lowest-indexed action greater than the current one that has not been used in the last three reviews
- Filter for Effective Actions: Construct a set of valid actions, $A_{\text{valid}}$, by filtering history $H$ for actions whose a.avg_loss falls within the Effective Learning Window of $[0.3,1.2]$
- Select Optimal Anchor: From the actions in $A_{\text{valid}}$, identify the one with the highest difficulty (i.e., the one with the largest Action ID, from “A” to “P”). This action is selected as the anchor to seed the Lock-in phase
- Fallback: If $A_{\text{valid}}$ is empty, this is treated as a curriculum calibration failure rather than forcing an unsupported anchor choice. The system should re-examine the difficulty intervals, loss thresholds, or candidate pool, and optionally perform an additional exploration round before entering the Lock-in phase
- Upgrade Condition: Increase difficulty by 1 step if either is met:
- Downgrade Condition: Decrease difficulty by 1 step if there is a relative loss increase of $\geq 30\%$
- Maintain Condition: If neither of the above is met, maintain the current action (arXiv:2603.16455)
