## Summary

This paper addresses the challenge of efficiently computing (α,β)-cores in large bipartite graphs, where vertices must meet minimum degree thresholds within their subgraph. Existing CPU-based methods are inefficient due to high memory usage for storing index structures across all possible α and β values. The authors propose GCC and GCC+, GPU-accelerated peeling algorithms that avoid this costly indexing by processing graph data warp-centrically or pruning early based on nested core properties, respectively.

Additionally, they tackle the related problem of real-time (α,β)-core membership queries for edge updates using an algorithm called GFQ. This leverages connectivity information to significantly narrow down computations and prevent full-graph peeling where necessary.
Their extensive experiments show that both their computation algorithms (GCC/GCC+) and query algorithm (GFQ) outperform existing CPU-based techniques on various large datasets, offering superior space and time efficiency for billion-scale graphs using GPU architectures.

## Technical note

This work is the first to compute (alpha,beta)-cores of bipartite graphs and answer on-the-fly edge-membership queries on GPUs, avoiding the prohibitive memory of CPU index structures (over 250 GB on a 4x10^8-edge graph). GCC is an index-free two-phase peeling algorithm: a scan phase using flat ID-based parallel filtering across both bipartite layers, and a peel phase using warp-centric execution where each warp collaboratively processes a vertex and its neighbors to reduce thread divergence under skewed degrees. GCC+ adds lightweight core-number-based pruning to skip vertices whose membership is pre-determined. GFQ answers on-the-fly queries after an edge update by localizing GPU peeling to the affected connected component rather than recomputing the full graph. Across 11 datasets, GCC+ gives >=1 order-of-magnitude query speedup and GFQ up to 175x over index-maintenance baselines, targeting real-time uses like fraud monitoring and recommendation.
