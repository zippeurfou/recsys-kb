## Summary

1.  Existing storage models struggle to efficiently handle hierarchical knowledge bases (HKBs) that are query-intensive and constantly evolving. The authors recognize this limitation as an implementation detail hindering progress in retrieval-augmented applications.
2.  To address these challenges, they propose WikiKV, a novel path-indexed key-value storage model with three core components: data-driven schema induction & evolution, ensuring consistency protocols prevent partial reads during concurrent updates without locking specific paths, and search-accelerated navigation operators that efficiently route queries to relevant sections of the HKB.
3.  Evaluated on real-world tasks and benchmarks (AuthTrace), WikiKV demonstrates high answer correctness (63.2%) while achieving significantly lower query operator latency compared to several existing RAG baselines and backend types, proving its effectiveness for hierarchical knowledge navigation workloads.

## Technical note

WikiKV is a path-indexed key-value storage model purpose-built for LLM-curated hierarchical knowledge bases (tree-structured wikis over a corpus) used as RAG substrates. It encodes the wiki schema (Index->Dimension->Entity->Digest->Document) directly into the key space so a directory listing is served by a single O(1) point lookup, and adds a data-driven schema layer with Intent-Anchored Schema Induction plus Continuous Evolution Operators (merge/split) and a cross-batch Error Book. A parent-after-child write protocol provides a consistency proof that online reads never observe partial states under concurrent offline rewrites without read-path locking, and a budgeted NAV(q,B) operator uses search-accelerated routing to compress expected LLM-assisted descent from O(depth) to O(1) with anytime semantics. Deployed for the WeChat Official Account AI Assistant, it reaches 63.2% end-to-end answer correctness with balanced low per-operator latency versus relational, graph, and filesystem backends.
