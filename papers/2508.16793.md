## Summary

1.  The paper addresses **Conditional Retrieval**, a variant of recommendation systems where items must be relevant to specific conditions (like topics) during retrieval, unlike standard two-tower models that don't inherently consider these filters.
2.  It proposes a method to utilize existing two-tower model training data for conditional retrieval by incorporating item-side information as the condition within the user query, thus encouraging interactions between users and conditions without needing new labeled data or separate tower training.
3.  Experiments demonstrate this approach retrieves highly relevant items under given conditions and improves performance (by +0.26% weekly active users) compared to standard two-tower models when filtering is applied, proving its viability for real-world deployment like Pinterest's topic-based notification feed.

## Technical note

This work tackles conditional retrieval, where retrieved items must be relevant to a condition (e.g., a topic), using the same engagement training data as a standard two-tower model. It adds a Condition Extraction Module that samples an artificial condition from item-side features (e.g., an item-to-topic mapping) and a Conditional User Tower that encodes the condition in the embedding layer so it can cross with user features; training uses in-batch negatives with a sampled-softmax contrastive loss. This lets new conditional use cases be bootstrapped without dedicated engagement data and jointly optimizes engagement and condition relevance. Deployed for a topic-based notification feed at Pinterest, the conditional model raised topic-matching rate from 20.3% to 82.8% (cutting ANN serving cost versus filtered two-tower) and drove +0.26% weekly active users.
