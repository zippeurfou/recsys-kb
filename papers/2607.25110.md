## Summary

This paper introduces "Memory Layer" as an optimized solution for recommendation systems where embeddings were previously only cached during serving, causing quality issues and latency constraints due to a training-serving representation gap.

The Memory Layer integrates the cache directly into the model (key-value store), embedding it alongside the user tower. This ensures consistent item representations are used both during training and when generating recommendations ("one source of truth").

Deployed successfully on Instagram Reels, this approach achieves 100% prediction coverage with fresher embeddings, improves recommendation recall for new content significantly, reduces cold start engagement issues, and lowers operational costs by eliminating separate embedding computations.

## Technical note

The memory layer is a co-trained in-model key-value item-embedding cache for early-stage (pre-)ranking that removes the training-serving representation discrepancy of the conventional two-tower folded architecture, where item embeddings are precomputed and cached outside the training loop. The item tower writes embeddings into a shared Multi-Probe Zero-Collision Hashing (MPZCH) table during training via an exact Writeback (eta=1 SGD) assignment, the predictor reads the same table at serving, and always-on content features cover cache misses so every item is scored, with Raw Embedding Streaming propagating updates in about 20s. Deployed on Instagram Reels, it raises prediction coverage from 96% to 100%, cuts embedding freshness from O(5min) to O(20s), and narrows the training-serving Normalized Entropy gap by up to 86% (pselect 12.11% to 1.64%). Online A/B shows over 2x recall for content under 5 minutes old, +5-6% cold-start engagement and breakout, and 30% lower training-and-publish compute at neutral serving cost. It is a training-serving co-design, not a unified generative pipeline.
