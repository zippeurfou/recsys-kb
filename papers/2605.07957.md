## Summary

Software test scripts can be faulty, but debugging them (Test Code Fault Localization - TCFL) is challenging and receives less attention than debugging the main system. This paper introduces SPARK, a framework that uses Large Language Models (LLMs) augmented with retrieved, similar past debugging knowledge to pinpoint faults in failing test scripts. SPARK retrieves relevant historical test cases and uses their fault patterns to guide the LLM's analysis, improving fault localization accuracy while maintaining efficiency, especially for complex test cases.

## Technical note

SPARK targets Test Code Fault Localization (TCFL), where failures originate in faulty system test scripts rather than the system under test, a black-box setting with limited diagnostic signals where spectrum-based methods are inapplicable. It integrates accumulated CI debugging knowledge into LLM-based reasoning: given a failing test, it retrieves a few similar fault-labeled cases from a debugging corpus, extracts their faulty lines, and selectively annotates textually similar suspicious lines in the query test. This annotation-based retrieval avoids the prompt-length explosion of naive RAG and needs no fine-tuning. On three industrial Python datasets, SPARK improves top-1 precision/hit by 10.1-19.1pp and Hit@3 by 17.7-25.5pp at near-identical inference cost.
