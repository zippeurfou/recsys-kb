## Summary

Existing search methods for platforms like WeChat often rely on fixed hierarchical Semantic IDs, limiting effectiveness for multi-topic documents.
WeSearch addresses this by being a model-centric framework that first retrieves relevant query clusters and then ranks individual documents within those clusters, decoupling pruning and relevance modeling.
The system, combining relevance training, compact document representations, and incremental updates, achieved significant improvements in click-through rate and article clicks while reducing retrieval costs and latency in large-scale production deployment.

## Technical note

Hierarchical Semantic-ID generative retrieval assumes each document follows one coherent semantic path and prunes irrecoverably on early-token errors, which breaks for multi-topic WeChat articles and graphic-text posts. WeSearch (Tencent) instead scores the query embedding against two-level RQ-KMeans cluster centroids (2k x 1k), unions the top-10,000 clusters' members as a query-specific candidate pool, shortlists them with ADC lookups over OPQ(64,256) document codes, and reranks the top-P with a feature-aware FFN over the query embedding, the reconstructed document embedding and bucketed quality, behavior and temporal features; a cluster softmax loss, a listwise document cross-entropy (target forced into the top-P) and a pairwise margin loss are trained jointly, with the OPQ rotation and codebooks kept as model parameters so quantization is optimized for retrieval. Positives come from relevance grades, satisfaction and consumption signals and negatives from lower-grade, position-aware weak-click and retrieval hard negatives; rolling training continues from the previous checkpoint weekly (daily when needed) instead of the previous monthly embedding refresh, and rolling mounting assigns fresh documents to the fixed cluster space and codebooks within minutes without rebuilding the index. Offline on the Base corpus the SID generative retriever underperformed even the production baseline while WeSearch beat it, OPQ(64,256) gave Recall@300 51.5% vs 33.1% for a 32-d dense vector, and document features plus mining raised Recall@100 on long-dwell and effective-click query sets from 0.44 to 0.55. Deployed as the primary semantic path beside a single lexical syntax tree over billions of documents, a one-month full-traffic A/B test showed +0.68% CTR, +0.71% dwell time and +2.27% per-user article clicks, with 41% lower retrieval resource cost and 19 ms lower graphic-text retrieval latency; it now serves 100% of WeChat Search traffic.
