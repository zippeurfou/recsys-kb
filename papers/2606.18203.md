## Summary

This paper addresses the challenge of reliably evaluating LLM personal health agents designed to use user sensor data. The authors introduce RubricsTree, a novel framework built using an extensive taxonomy (>100 Boolean rubrics) derived from expert physician input and 4,000 real user queries through iterative curation. This system provides context-aware evaluation by activating only relevant rubrics per query, effectively optimizing for both scalability and alignment with clinical expertise compared to existing large-scale evaluation baselines.

## Technical note

RubricsTree is a scalable evaluation framework for open-ended personal-health LLM agents built on an expert-aligned hierarchical taxonomy (DAG) of 100+ atomic, clinically-verifiable Boolean rubrics, curated over 4,000 real user queries via a human-in-the-loop panel led by a physician. Each leaf is a binary verification function grounded in clinical references, and a top-down equal-weight distribution assigns each leaf a normalized weight equal to the product of inverse child counts along its path. A context-aware adaptive router activates only the query-relevant rubric subset per query for throughput, and a meta-evaluation protocol measures the evaluator itself via ICC3, Cohen's kappa, and oracle-based contextual-perturbation detection. Used as structured instructions or as a reward signal, it yields up to ~66% relative gains on HealthBench for Gemini, GPT, and Qwen families, with strong expert alignment (ICC3 0.876).

## References

- Contextual Triage: The agent parses the user’s query against its available tool schema. It identifies knowledge gaps and determines the specific physiological data or baseline demographics required to safely address the query
- Execution (Action): Generation is temporarily halted to emit a structured function call. For example, the agent may invoke the wearable database to fetch specific metrics over a defined timeline
- Observation: The external tool executes the requested routine against the data backend, returning a serialized string of the requested telemetry (e.g., longitudinal laboratory results or 7-day rolling sensor trends)
- Synthesis & Response: The agent ingests the observation into its context window. It then evaluates if the aggregated data is sufficient to formulate a clinically sound response. If missing variables remain (e.g., retrieving blood glucose but requiring fasting insulin to calculate resistance), the agent loops back to Step 1
- Embedding Similarity. Each leaf $l_{i}$ is represented by a dense embedding of its textual description. The relevance score $g(q,c,l_{i})$ is computed as the cosine similarity between the query embedding and the leaf embedding, with a threshold $\tau$ tuned globally on a held-out development set
- Binary Per-Leaf Judge. For every leaf $l_{i}$, an LLM is prompted with the tuple $(q,c,l_{i})$ and asked to emit a binary “relevant / not relevant” decision. This is structurally the most direct way to instantiate $g\in\{0,1\}$ but requires $|L|$ independent LLM calls per query
- Hierarchical Tree Traversal (Ours). An LLM router traverses the curated taxonomic DAG from the root, expanding only the children of nodes whose parent has been judged contextually relevant; this is conceptually related to Tree-of-Thought prompting , but operates over a fixed, expert-given tree rather than a router-generated one. The per-query activation threshold $\tau(q,c)$ is dynamically decided by the router (arXiv:2606.18203)
- Keyword/Context Relevance: The rubric is strongly related to the query’s clinical intent
- Response Utility: The response would be significantly clinically improved by incorporating information from the rubric
- Trigger Condition Matching: The query fits the specific trigger condition of the rubric (e.g., specific biomarker inquiries)
- Reasoning: A short, concise sentence explaining the clinical rationale
- Binary Score: A [1] if the response satisfies the rubric, or a [0] if it fails (indicating clinical negligence, omission, or inaccuracy)
- Seamlessly insert necessary additions or follow-up questions to address missing context flagged by the auditor
- Only delete or modify original statements if the auditor explicitly flagged them as incorrect, unsafe, or definitively harmful
- Overall Score: aggregated performance across all specific evaluation axes, serving as a holistic measure of both clinical safety and conversational quality on the HealthBench-Hard dataset
- Completeness: whether the model comprehensively addressed all facets of the user’s complex query without omitting critical medical details, caveats, or necessary follow-up steps
- Context Awareness: how effectively the model integrated and adapted its advice to the user’s specific personal context, implicit needs, or provided demographic/health data (arXiv:2606.18203)
