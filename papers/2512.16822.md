## Summary

LLM applications with long, shared prompts face high memory pressure from their Key Value (KV) cache. While position-independent caching (PIC) allows chunk reuse across different prompt positions, it suffers from inefficiencies due to per-request recomputation and non-aligned memory layouts, leading to only modest memory savings. The paper introduces MEPIC, a system that overcomes these limitations by aligning KV cache to pages, shifting recomputation to block-level, and integrating positional embeddings, enabling significant memory reduction (up to 5x for long prompts) without sacrificing latency or accuracy.

## Technical note

MEPIC targets HBM memory pressure in LLM serving where many requests reuse the same document chunks but position-independent caching (PIC) yields only modest savings due to per-request recomputation and non-aligned KV layouts. It aligns chunk KV to fixed-size pages, shifts selective recomputation from token-level to block-level (recomputing only the first block per request), and stores KV in a NoPE format with RoPE fused into the attention kernel so blocks become position-agnostic and shareable across requests and batches. Integrated into vLLM+LMCache, it reduces peak HBM usage up to 2x on multi-step RAG and 5x on long prompts while matching CacheBlend/EPIC accuracy and lowering end-to-end latency 9-11%.
