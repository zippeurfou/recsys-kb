## Technical note

GRAB (Generative Ranking for Ads at Baidu) is an end-to-end generative CTR framework that fuses DLRM-style large-scale sparse feature engineering with GR-style causal-transformer sequential modeling. It introduces a Causal Action-aware Multi-channel Attention (CamA) mechanism to model heterogeneous exposure and interaction action signals in user behavior sequences, and a Sequence-Then-Sparse (STS) training strategy that decouples optimization of dense transformer weights and sparse embeddings to resolve distribution skew / gradient conflict caused by sequence packing (excessive intra-user correlation violating i.i.d.). Offline GRAB beats mainstream DLRMs and GR baselines (+0.19% over best), and full online deployment at Baidu delivered ~2bp AUC uplift, +3.05% CPM, and +3.49% CTR, with AUC improving monotonically with model capacity and behavior-sequence length.

- Ad Representation: The system generates ad tokens corresponding to candidate advertisements
- Data Collection and Storage: Logs are collected and stored in behavior storage, which organizes data into User (user_id, gender), AD (ad_id, brand), and Context (location, device, behavior) categories
- Feature Engineering: The system performs sparse feature engineering on the collected logs
- Training: Training data is grouped by user ID (uid) to facilitate model offline training
- Deployment: Updated models are pushed back to the online environment via an hourly release mechanism, updating the CTR prediction and user model components
- Computational Complexity: Unlike memory-bound DLRMs, GR in this context is compute-bound. This is primarily attributed to the quadratic complexity ($O(L^{2})$) of Transformer self-attention mechanisms required for processing long sequences
- Latency Requirements: The system’s performance is bound by critical latency thresholds defined in the Service Level Agreements (SLAs) (arXiv:2602.01865)
- L1 (GPU HBM): Stores hot embeddings for the current micro-batch
- L2 (CPU DRAM): Buffers warm parameters
