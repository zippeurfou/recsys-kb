## Summary

1. Long-horizon agents face high costs when retrieving large amounts of stored evidence for answers, even if that specific evidence isn't needed. The challenge is selecting which relevant evidence to keep *before* knowing the query within a fixed token budget.
2. EMBER addresses this by using a learned retention policy ("Budgeted Pre-Query Retention") during the ingestion phase, focusing on keeping useful source evidence verbatim in "capsules" with retrieval keys and update metadata for efficient future access without reprocessing large amounts of data.
3. By training its writer component based on feedback from past answers to ensure retained capsules are relevant, EMBER significantly improves performance (measured by F1 score, Retain-Recall, and Read-Recall) compared to other budgeted methods or unstructured storage, demonstrating the importance of strategic evidence retention for long-horizon memory agents.

## Technical note

EMBER is a learned retention policy for long-horizon agents that selects, before the query is known, which source evidence should stay recoverable under a fixed retained-evidence token budget, framed as Budgeted Pre-Query Retention. Memory is written during ingestion as evidence capsules (verbatim source excerpts paired with retrieval keys and update metadata) that preserve both grounding and read-time access without revisiting the full raw stream. The writer is trained across the ingestion-retrieval-answer chain using post-query outcome feedback so retained capsules are answer-relevant. On LongMemEval-RR, EMBER-14B reaches 0.3017 F1 at the 8192-token retained-evidence point versus 0.1765 for the strongest non-EMBER budgeted baseline, improving F1, Retain-Recall, and Read-Recall across budgets.
