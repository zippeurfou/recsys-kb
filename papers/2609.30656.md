## Summary

Large-scale recommendation systems face complex profiling challenges due to their structurally heterogeneous nature, mixing various hardware-bound operations. Component Benchmark (CB) addresses this by independently profiling each submodule with a hierarchical framework and plugin architecture. It provides a tree-structured visualization, offering performance clarity crucial for optimizing these massive, compute-intensive models.

## Technical note

Meta's Component Benchmark (CB) closes the gap between end-to-end throughput numbers and operator-level traces (Kineto, Nsight, PyTorch Profiler) when optimizing heterogeneous, TB-scale recommendation models that train continuously on thousands of GPUs over ~100B examples per day. CB registers PyTorch forward hooks to capture each submodule's runtime inputs, then profiles every submodule independently on a single GPU in breadth-first order (shrinking embedding hash sizes, replicating small captured batches to avoid OOM, and aggregating children when a parent does not fit), reporting latency, memory, TFLOPS, MFU and bandwidth per module in a hierarchical table and interactive icicle view built on a ~1000-line plugin core. On TorchRec's DeepFM DLRM it shows sparse_arch is memory-bandwidth-bound and that deep_fm (27% MFU) is compute-bound while the FM cross term (0.06% MFU) is bandwidth-bound; on NanoGPT, attention runs at half the MLP's MFU. In production, CB analyses yielded a 3% training and serving throughput gain by replacing GEMV kernels with elementwise ops that enlarge PT2 fusion regions, a 34% QPS gain after sizing whole-model PT2 compilation in isolation (83 to 50 ms per iteration), and 10% QPS plus 22% memory recovered by localizing a generative-recommender ranking model's 2.8x memory regression to its event model and set-transformer blocks.
