## Summary

1.  Testing REST APIs is crucial for microservices, but existing specification-based tools (like Swagger/OpenAPI) often fail to adequately test complex, business-sensitive functionalities due to missing business constraints.
2.  This paper introduces LoBREST, a novel testing technique that uses historical request logs (HRLogs) to extract necessary business constraints, partitioning and enhancing these logs to generate effective test sequences.
3.  LoBREST significantly outperformed eight existing tools across 17 real-world services, achieving top coverage on most and detecting 108 bugs, 38 of which were found exclusively by LoBREST.

## Technical note

LoBREST is a log-based, business-aware REST API testing technique that extracts business constraints from historical request logs (HRLogs) rather than relying only on Swagger/OpenAPI resource constraints, which miss business-sensitive functionalities like 'merge branch after approval'. It applies a locality-slicing strategy to partition HRLogs into compact operation-sequence slices, enhances them by adding slices for missing operations and completing missing resources, then uses the enhanced slices as seeds for business-aware fuzzing to improve test adequacy. Evaluated on 17 real-world REST services against eight tools including Arat-RL, Morest, and DeepRest, LoBREST achieved the highest operation coverage on 16 services and highest line coverage on 15, covering on average 2.1x as many operations and 1.2x as many lines as the second-best tool. It detected 108 5XX bugs total, 38 found exclusively by LoBREST.
