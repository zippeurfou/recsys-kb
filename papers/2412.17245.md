## Summary

1.  Deep recommender systems face memory constraints due to large embedding tables needed for high-cardinality features like user and item IDs.
2.  GraphHash addresses this by using modularity-based bipartite graph clustering on the user-item interaction network during preprocessing, serving as an efficient alternative to traditional hashing methods that ignore collaborative signals.
3.  This approach significantly reduces embedding table size while improving performance (both retrieval metrics and CTR prediction) compared to standard baselines, demonstrating substantial value from incorporating graph structure for model compression.

## Technical note

Deep recommenders need huge embedding tables for high-cardinality features like user/item IDs, straining memory. GraphHash replaces traditional hashing (which ignores collaborative signals) with modularity-based bipartite graph clustering on the user-item interaction network during preprocessing, assigning entities that share collaborative structure to the same embedding buckets. This substantially reduces embedding-table size while improving both retrieval metrics and CTR prediction versus standard baselines, showing that graph structure adds value for model compression.
