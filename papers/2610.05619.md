## Summary

Supply-Aware Cold-Start Proactive Query Suggestion for Travel Search":

1.  Generative query suggestion using LLMs is effective for open-ended searches, but travel search differs due to its physical inventory limitations.
2.  Traditional travel search interfaces lack user query logs and seed inputs, creating a "cold-start" problem for suggesting relevant queries proactively.
3.  The paper introduces SCOUT, a framework that uses supply-side system feedback (query-listing match scores) within a reinforcement learning setup to train proactive suggestions, achieving a significant improvement in matching available inventory while keeping costs low.

## Technical note

SCOUT bootstraps free-text query suggestions for travel search, which has no historical free-text query logs or seed queries (a cold start) and whose suggestions must match physical inventory, so the model generates them proactively from the structured search context of destination, dates and guest count. It treats the live search engine as an RL environment and rewards each sampled slate of two suggestions with R18, the mean semantic match score that the production reranker already assigns to the top 18 listings per suggestion, which costs no extra inference and correlates with the LLM-judged inventory match rate IMR@18 (Spearman 0.45). The policy is Qwen3-8B with LoRA (rank 32) trained by GRPO (group size 8, KL weight 0.06, fully on-policy), evaluated on destination-disjoint splits with IMR@18 from an LLM judge calibrated against a human-labeled golden set and a diversity metric, distinct%@0.9, from MiniLM embeddings clustered at cosine 0.9. Against few-shot prompting, SCOUT lifts R18 by 37.63% and IMR@18 by 12.30% with diversity held at 83.72 vs 84.03 distinct%, beating rejection-sampling fine-tuning on the same reward (+1.75% IMR@18) and RPO (+6.02%), while plain DPO collapses diversity to 11.07 distinct% through likelihood displacement. SCOUT matches a serve-time best-of-8 policy, covering 81% of the gap from best-of-1 to best-of-16, without issuing any search calls per request, which is what makes it deployable on a real-time travel search path.
