## Summary

1.  This paper challenges the common assumption that vector search algorithm performance solely depends on distance computation costs, showing that system-level overheads (like page accesses and filter checks) are crucial in a production database environment.
2.  It provides the first in-depth analysis of filter-agnostic vector search algorithms within a PostgreSQL-compatible system, comparing post-filtering and inline-filtering strategies, and evaluating graph-based (NaviX/ACORN) and clustering-based (ScaNN) approaches across different selectivities and correlations.
3.  The key finding is that the optimal algorithm depends on system-aware factors and workload characteristics, often negating the theoretical advantages of graph-based methods due to high real-world overhead, and advocating for a system-specific choice rather than just algorithmic efficiency.

## Technical note

This is an experimental study of filter-agnostic Filtered Vector Search (FVS) inside a production PostgreSQL-compatible DBMS, challenging the assumption that ANN performance is governed by distance-computation cost. The authors show that DBMS system overheads (8KB page accesses, TID indirection requiring a double index-then-heap lookup for filter columns, constrained parallelism) can dominate, making library benchmarks that minimize distance computations an unreliable proxy for end-to-end latency. They compare graph-based (HNSW, NaviX/ACORN-style inline filtering) against clustering-based (ScaNN) indexes across a full spectrum of filter selectivities and vector-predicate correlations using a novel dataset-agnostic workload generator on 5-10M-vector datasets. The key result is that graph methods incur prohibitive filter checks and page accesses that often cancel their theoretical advantages, shifting the selectivity cross-over point, so the optimal FVS algorithm is a system-aware decision contingent on workload and data-access costs.
