## Summary

1.  **Problem:** Standard RL algorithms like GRPO struggle with weak, surface-level feedback (compile-time success/failure) during code repair, which doesn't capture the deeper semantic goal of producing correct functionality.
2.  **Solution:** The authors propose "signal reshaping" for GRPO, involving three key changes: using layered rewards (compile + semantic success), weighting step-level process scores for better credit assignment, and improving rollout comparability to overcome weak feedback limitations.
3.  **Result:** Experiments show that this signal reshaping significantly improves code repair accuracy (from 38.5% to 53.5%) and efficiency, demonstrating that simple feedback methods like binary compilation success are insufficient, and the reshaping techniques are necessary for effective agentic code repair.

## Technical note

This paper studies signal reshaping for GRPO in weak-feedback agentic code repair, using compile-fix where rollout signals check only necessary/surface conditions rather than semantic correctness. It argues GRPO's within-group comparison is meaningful only after three signals are reshaped: layered compile-and-semantic outcome rewards (0/0.5/1) recover semantic ranking, step-level process scores as token-level loss weights localize intra-trajectory credit, and failure-cause-aware rollout governance keeps same-prompt rollouts execution-comparable. These changes leave GRPO's group-normalized advantage unchanged yet raise strict compile-and-semantic accuracy from 0.385 to 0.535 and cut evaluation steps from 23.5 to 17.0. Privileged-prompt token-level distillation underperforms, indicating KL-style local matching cannot replace outcome semantics or process credit.

- *Resource mapping*: compile_code calls and the final compilation check at trajectory termination use the compilation resource pool; file editing, command execution, and environment reset use the sandbox resource pool
- *Inference-slot release*: inference resources cover only a single model-generation request and do not cover subsequent tool execution, so tool I/O can overlap with other rollout generations
- *Compilation concurrency constraint*: compilation tasks are queued under a conservative concurrency limit to prevent CPU, memory, and I/O contention from contaminating the execution opportunity of rollouts in the same group
- *Cascading protection for compilation timeouts*: if a single trajectory experiences at least the compile-timeout abort threshold (default $2$) consecutive compilation timeouts, it is proactively terminated at the next step and marked as consecutive_compile_timeouts. This prevents a small number of toxic samples from continuously occupying compilation channels and slowing down the entire rollout batch
- *Full-trajectory masking*: context_limit, abort, max_tokens, consecutive_compile_timeouts, and environment_setup_failed. Final compilation and semantic judgment are skipped to save evaluation budget
- *Last-step retention*: catastrophic_repetition and excessive_tool_calls, implemented as mask_except_last_step
- *Normal settlement*: finish_called, max_steps, and no_tool_call_stop (arXiv:2605.07276)
- per-token KL in advantage ($\beta\!=\!1$): the gradient norm increases rapidly at the beginning of training, and the loss soon diverges
- masked mean KL in reward ($\beta\!=\!0.25$): the KL term remains very small for a long period and has limited effect on group-normalized relative returns; the training trajectory nearly overlaps with the pure GRPO baseline, with no stable gain observed
- masked sum KL in reward ($\beta\!=\!0.25$): the KL contribution fluctuates substantially with trajectory length, so the same $\beta$ corresponds to different penalty strengths for short and long samples; training becomes clearly unstable and terminates early
- masked sum KL in reward ($\beta\!=\!0.05$): this setting also exhibits length-coupled optimization instability. Although it is slightly milder than the larger coefficient, it still does not enter a comparable long-horizon interval
- masked sum KL in reward ($\beta\!=\!0.02$): this is the only masked-sum configuration that enters long-horizon comparison. Its explicit KL can be continuously reduced, but correctness evaluation does not outperform GRPO-early post-fork, and the run gradually shows termination-behavior degradation and low entropy. It therefore serves as a runnable but non-beneficial counterexample, rather than positive evidence that OPSD can replace GRPO’s signal conditions
- masked mean KL in reward ($\beta\!=\!50$): training can formally continue, but learning is clearly suppressed, eventually producing long-term reward degradation and interruption in the later stage

- Answer: [Yes]
- Justification: The paper’s main claim is limited to signal-reshaping conditions for weak-feedback agentic repair, and each claimed condition is tied to a corresponding controlled comparison: layered rewards are evaluated through the GRPO-early versus GRPO-binary contrast, process-level credit through the GRPO-early versus GRPO-full contrast, and token-level distillation is used as a boundary comparison. This keeps the claims aligned with the evidence actually reported

- Answer: [Yes]
