## Summary

Machine learning data loading pipelines often suffer from high latency due to the per-request overhead of fetching many small objects individually. To address this, the paper introduces GetBatch, a new object store API that treats batch retrieval as a single, atomic operation. This approach significantly improves performance, demonstrating up to 15x throughput gains for small objects and substantial reductions in batch latency percentiles (P95 by 2x, P99 by 3.7x) compared to individual GET requests.

## Technical note

GetBatch is an object-store API for ML data loaders that elevates batch retrieval to a first-class, deterministic, fault-tolerant streaming primitive, replacing thousands of independent GET requests with one request that returns a single ordered TAR stream. It combines the sampling randomness of random-access (map-style) I/O with the throughput of sequential shard I/O, avoiding shuffle buffers and stream multiplexers. Server-side execution uses a Designated Target (DT) selected by consistent hashing (or colocation hints) to coordinate; other nodes act as autonomous senders that stream locally owned objects/archive members peer-to-peer while the DT enforces strict request order and continue-on-error placeholders. Implemented in NVIDIA AIStore with a Python SDK, it achieves up to 15x throughput for small objects and reduces production P95 batch latency 2x and P99 per-object tail latency 3.7x.
