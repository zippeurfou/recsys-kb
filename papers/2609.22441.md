## Summary

LinkedIn's pre-ranking system, CC Retriever, addresses the challenge of scoring vast numbers of network-related content candidates (up to one billion initial, narrowed to tens of thousands) for its Feed. It achieves this by loading dense graph affinity features and document features onto GPUs and using a specialized "sorted-search" primitive to perform the necessary deep ranking model computations extremely fast. This GPU-based approach allows for a significant increase in model complexity (50x parameters) and delivers substantial online performance gains (+2.5% increase in Feed engagement time).

## Technical note

On the LinkedIn Feed, network (connected) content drives over 70% of impressions and engagement, and first- plus second-degree ('stranger viral') fan-out makes the candidate index exceed one billion, leaving tens of thousands of network activities per request to score within a 120 ms p99 budget. Connected Content Retriever scores these candidates with a full deep ranking model on GPUs (a GPU Retrieval-as-Ranking stack), built around a sorted-search GPU primitive that joins dense viewer-to-author graph-affinity edge features (tie strength, interaction recency, co-engagement, second-degree path statistics) with GPU-resident document features in 5-10 ms. Moving to GPU scoring enabled a 50x increase in ranking-model parameters and a +2.5% lift in content time spent in online experiments, well above typical Feed gains. Ablating edge features drops recall by 7.86%, showing graph signals that content embeddings alone did not capture.
