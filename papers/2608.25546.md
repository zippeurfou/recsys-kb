## Summary

Current LLM-based recommendation systems treat each interaction as a separate token, ignoring valuable user, item, context, and outcome information, leading to weaker queries throughout the sequence.

The paper proposes AMBER (Autoregressive Modeling via Bottlenecked Event Representation), which replaces individual tokens with compact "Event Tokens" encoding the full interaction details.

This event-centric approach allows AMBER to significantly improve recommendation quality on large benchmarks, demonstrating positive transfer and better scaling, even outperforming dedicated entity tokenizers and showing effectiveness across different architectures and tasks.

## Technical note

Meta proposes AMBER (Autoregressive Modeling via Bottlenecked Event Representation), an event-centric LLM recommender evaluated on petabyte-scale industrial logs and deployed on a full-traffic Facebook monetization surface, arguing the real scaling axis is 'snapshot resolution' -- how many heterogeneous signals are encoded per historical event -- rather than sequence length alone. An Event Tokenizer (4-layer bidirectional Transformer over projected sparse/dense/embedding features plus learnable CLS tokens, then an MLP into LLM embedding space, 3.84M dense params and ~200GB sparse tables) compresses each event's few-hundred user/item/context/outcome features into one compact Event Token, consumed autoregressively by a 1B-parameter Llama User LLM using timestamp-based RoPE. One shared tokenizer serves all roles via per-role feature masks: ranking interleaves a context token and a label token per event under autoregressive BCE, retrieval fuses one token per event and trains with InfoNCE over hard (shown-not-engaged) and random negatives for ANN user embeddings. Training is three-stage (freeze-LLM pre-alignment, joint unfreezing, sharded recurrent retraining); representation drift across retraining is suppressed with DANN adversarial regularization at lambda ~5e-3 plus an EMA reference encoder, and token storage is cut 8x via Matryoshka Dropout and INT8 quantization-aware training served at INT4. AMBER beats a compute-matched Incumbent ranker by 0.40% Normalized Entropy, Pointwise input by 0.30%, HSTU-style input by 1.00% and Semantic IDs + content-understanding embeddings by 1.60%; ensemble NE against the Incumbent improves 0.10% (10-min feature delay) and 0.16% (1-min), and retrieval Soft Recall gains +0.31% to +0.51% while CU embeddings decay to neutral by day 8. The headline scaling finding is that training-optimal is not system-optimal: User LLM scaling wins when only training FLOPs are counted, but cached asynchronous Event Tokenizer and snapshot-resolution scaling win once the 30-100x serving-to-training amplification and CPU feature materialization are included. Caveat: no online A/B lift is reported -- the production result is a ~0.06% NE reduction when the existing non-LLM ranker consumes cached Event Tokens as extra historical features (0.02% is their significance bar) -- and serving an end-to-end LLM ranker with KV cache over long histories is explicitly left unsolved.
