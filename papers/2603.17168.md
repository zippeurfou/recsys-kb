## Summary

Traditional GPU hash tables waste significant High Bandwidth Memory (HBM) by storing every key, which is inefficient for large embedding tables exceeding GPU capacity. The authors introduce HierarchicalKV (HKV), the first general-purpose GPU hash table designed with "cache semantics," allowing eviction during inserts instead of rehashing. HKV achieves significantly high performance, exceeding 3.9 billion key-value pairs per second with stable throughput across full utilization, and has been successfully integrated into recommendation frameworks.

## Technical note

HierarchicalKV (HKV) is a general-purpose GPU hash table that replaces the usual dictionary semantics (every key preserved) with cache semantics, treating policy-driven eviction as a first-class operation so a full table is the normal operating condition rather than an error. It co-designs cache-line-aligned single-bucket-confined buckets (128 one-byte digests in one L1 cache line for a definitive miss in one memory transaction), in-line score-driven upsert fusing score comparison, admission control and CAS, score-based dynamic dual-bucket selection extending power-of-two-choices to eviction quality, and triple-group reader/updater/inserter concurrency with a CPU-GPU dual-layer lock. Tiered key-value separation keeps keys/digests/scores in HBM while spilling values to pinned host memory, extending capacity beyond HBM. On an H100 NVL it reaches up to 3.9 billion key-value find operations per second with <5% variation across load factors 0.50-1.00, 1.4x WarpCore and 2.6-9.4x indirection-based baselines, and recovers ~34% HBM wasted by birthday-paradox collisions with 99.4% top-N score retention at full load. It has been integrated into NVIDIA Merlin HugeCTR, TFRA, and RecSys Examples since October 2022 for recommendation embedding caches.
