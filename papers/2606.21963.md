## Summary

This paper introduces **Holmes**, a multi-agent system designed to diagnose crashes in massive mixed-language mobile codebases at industrial scale. The challenge lies in effectively debugging without needing reproduction access or being constrained by traditional static analysis methods. Holmes synthesizes runtime signals (like stack traces, logs, and thread states) using its Retrieve-Explore-Reason architecture focused on low-level artifacts, enabling rapid diagnosis; it successfully localizes faults with 87.6% accuracy in large-scale WeChat applications, drastically cutting investigation time to under a minute.

## Technical note

Holmes is a multi-agent system that diagnoses mobile crashes in ultra-large-scale mixed-language codebases (C/C++/ObjC/Swift) without reproduction, using a hierarchical Retrieve-Explore-Reason architecture. Layer 1 runs parallel context-retrieval agents: a Stack Code Retriever that dual-mode fetches source for business logic and assembly for closed-source frameworks, a Log Miner that captures a 1-minute window and uses a semantic Map-Reduce over 8k-token chunks to keep causally relevant lines, and a Thread Inspector that ranks threads by relevance to detect deadlocks/races. Layer 2 replaces impractical global call graphs (>12h, >500GB) with an agentic search paradigm over a lightweight function-to-file index (~3.3h build, ~10min incremental), iterating up to 3 times to expand context toward non-local root causes in 70M-line, 6M-function repositories. Layer 3 synthesizes stacks, logs, thread states, and low-level artifacts (registers, memory, assembly) for diagnosis. On 73 annotated WeChat iOS crashes it achieves 87.6% pass@1 function-level localization and 65.7% root-cause identification, cutting investigation time by over 98% to ~77 seconds.
