## Summary

Feedback-Aware Cohort Memory for E-Commerce Recommendation":

1.  The paper introduces RecGroupMemory, a system designed to provide LLMs used in e-commerce recommendations with updated decision guidance based on recent user feedback.
2.  This system separates the initial construction of cohort memory (group-level user data) from its subsequent revision, using daily feedback to adapt the guidance while preserving the core underlying user observations.
3.  Online tests on Taobao showed that using RecGroupMemory with feedback updates increased the number of users completing guided transactions by 1.78% compared to a recommendation system without memory updates.

## Technical note

Taobao, users with low purchasing power selected by the business team. Problem: an orchestration LLM that plans the recommendation workflow per request can be given cohort-level memory (a group Profile and Advise), but delayed browsing and transaction outcomes mean the guidance must be revised without letting free regeneration silently alter the recorded observations it rests on. Method: RecGroupMemory separates memory construction (an Evidence Extractor organizes event, experiment and context memory into Shallow Memory; a Memory Builder synthesizes cohort records) from a nearline Memory Refiner that left-joins the current record C_T with previous-day feedback F_(T-1) by Memory ID (signed relative metric changes delta = q/q_base - 1 against the same-profile first-guess feed; missing values must not be read as neutral), rewrites only Profile, Advise and structured advice strengths in {-2..2} for CTR, IPV, CVR and GMV through clip(a_q + delta_q), and a validator pins seven source fields (schema version, cohort, recommender version, scope, segment, observation window, aggregated metrics) with at most one repair attempt and fallback to C_T; CVR strengthening is permitted only when both transaction-UV and order-count deltas are present and positive. Results from two online comparisons, each against its own no-memory baseline: memory without feedback +1.58% transaction UV, +0.80% orders, +1.60% PCVR; feedback-aware memory +1.78%, +2.05%, +1.95%, with exposure and click UV within +/-0.5%. The authors note the two arms do not directly estimate the incremental value of feedback, that Memory-ID linkage does not establish causal attribution since feedback depends on the policy that generated it, and that revision safeguards still depend on the prompt rather than enforced constraints.
