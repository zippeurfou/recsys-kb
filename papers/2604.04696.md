## Summary

Modern Private Information Retrieval (PIR) protocols require heavy server-side computations like Number Theoretic Transforms (NTTs) and large-scale matrix multiplications (GEMMs), which are inefficient on GPUs due to memory bottlenecks caused by multi-client batching.

The paper introduces GPIR, a GPU-accelerated system that tackles this by implementing a stage-aware hybrid execution model, dynamically switching between operation-level kernels and fused stage-level kernels to maximize data reuse.

GPIR further addresses specific performance gaps in the RowSel phase through layout optimization and pipelining, and extends to multi-GPU systems with minimal overhead, achieving a 305.7x performance improvement over existing GPU-based PIR systems.

## Technical note

GPIR is a GPU-accelerated OnionPIRv2 system that targets the three PIR phases (ExpandQuery, RowSel, ColTor) under multi-client batching, which shifts bottlenecks from bandwidth to a 'cache-capacity wall' and layout inefficiency. It introduces a stage-aware hybrid execution model that switches between operation-level kernels (high occupancy when L2-resident) and fused stage-level kernels (minimizing DRAM traffic once the working set exceeds L2). RowSel is reformulated as 4N parallel point-wise GEMMs and accelerated via a transposed-layout design plus fine-grained p-dimension pipelining (prime-level and N-chunked partitioning with CUDA Graphs) to overlap transposes with GEMMs. Multi-GPU execution uses DB sharding with response aggregation and all-gather of expanded ciphertexts over NVLink, achieving up to ~297-305x throughput over PIRonGPU.
