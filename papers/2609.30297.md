## Summary

Spotify developed a system to bootstrap conversational recommendation agents, which are challenging to optimize, especially when there's little user data (cold-start). This system uses a synthetic data pipeline to generate realistic multi-turn conversations and a self-improvement loop employing contrastive optimization and iterative refinement via a coding agent to identify and fix errors. The approach demonstrably improves agent quality by 8% and boosts performance in A/B tests, with a 14% increase in user listening, 5% more weekly active users, and a 5% lower skip rate compared to prior methods.

## Technical note

Spotify had to launch an LLM conversational recommendation agent, which plans tool calls over existing search and recommendation services, before any multi-turn traffic existed, so it built a synthetic evaluation pipeline and an automated prompt-improvement loop. The pipeline defines five multi-turn capabilities (Content Refinement, Instruction Retention, Anaphora Resolution, Intent Shift, Separate Input), has a DialogPlanLLM expand real and synthetic single-turn seed prompts into abstract dialog plans, realizes each plan against the live agent with a UserLLM that adapts turns to the agent's actual replies, and scores only the final turn with a capability-specific rubric in an LLM-as-a-judge. The loop samples k plans per query at temperature 0.7 to 1.0, uses the gap between pass@k and pass^k (32% at k=5) to separate reliability failures from capability gaps, attributes variance to planning rather than tool, infrastructure, or judge noise, and has a coding agent apply contrastive optimization over successful versus failed plans, or iterative refinement for queries that never pass, editing prompts and tool descriptions in mini-batches of 8 that it re-checks at temperature 0 before humans review the resulting PR. Annotators rated the synthetic conversations above 90% on all four quality checks (judge accuracy 97%), pass@1 held for 2 to 4 turns and fell from 5 turns on, Instruction Retention and Content Refinement were hardest, and the loop raised pass@1 by 8% relative over an already hand-optimized prompt on about 1,000 examples (sign test p=0.01). A two-week A/B test on about 15M users showed +14% listening, +5% weekly active users, and a 5% lower skip rate versus a session-refinement-only experience, and the agent then rolled out to production.
