## Summary

FlashTrie presents an optimized GPU implementation of constrained beam search, a critical technique in generative retrieval where generated text must match specific document IDs. It achieves this by significantly reducing memory stalls through bit compression and parallel primitives replacing CPU-style operations. This results in drastically lower latency (under 3ms for large libraries) and higher throughput compared to multi-threaded CPU baselines, enabling real-time constrained decoding at scale which was previously only feasible offline.

## Technical note

FlashTrie accelerates the constrained decoding step of generative retrieval, where autoregressive/non-autoregressive decoders must emit only document IDs present in a valid library, usually enforced by CPU trie-constrained beam search that bottlenecks as beam width grows. It introduces an integer-aware succinct trie (extending MARISA/Narrow-LOUDS to 32-bit tokens with bit-compression so an 800M-key, ~3GB index fits in GPU HBM) and a single cooperative CUDA kernel that runs beam expansion, validation, and pruning on-device with two-level (beam-parallel and proposal-parallel) concurrency, parallel binary-search child matching, and heap-free block-merge-sort top-B selection. On an 800M-keyword library at beam widths up to 1000, it keeps trie-search latency under 3ms (up to 24x faster than an optimized multithreaded CPU MARISA-Opt baseline), builds 3.4x faster with a 22% smaller index, and reaches ~70x higher throughput, while matching CPU retrieval precision within 0.001 (P@100 rising 0.53 to 0.78 with beam width). In a 16-day commercial sponsored-search A/B test, the recovered latency headroom (raising beam width from 200 to 600) yielded a statistically significant +0.71% revenue lift and +0.17-0.20% more clicks.
