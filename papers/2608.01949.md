## Summary

Push notification recommendation is crucial for long-term user re-engagement but challenging due to the complex "when" decision under resource constraints. Existing approaches often use passive pre-planned frequency schedules or fixed-interval polling, leading to inefficiencies and suboptimal outcomes from local optima traps. To address this, the paper introduces STEPS, a self-triggered agentic system using Decision Transformer agents for planning (next invocation) and execution (push sending), along with a lightweight filtering agent to manage computational cost. Online A/B testing shows STEPS significantly improves user active days (+0.2843%) while reducing push permission disablement (-1.9089%), demonstrating its effectiveness compared to traditional methods.

## Technical note

Douyin's push-notification stack must solve the "whether and when to send" problem, but pre-planned frequency methods (offline uplift modeling + integer programming) ignore real-time context while fixed-interval polling either wastes compute or misses good moments. STEPS reframes it as a self-triggered closed loop with three agents: a decision-transformer planning agent that emits the next self-invocation time gap, an execution agent that decides send/no-send, and a lightweight filtering agent. Two mechanisms make the DT work at scale: a Gated-RTG condition injection (return-to-go passed through an MLP and applied as a Hadamard gate on the state embedding, instead of concatenation, raising the RTG/action correlation ratio from ~1.0 to ~1.8) and ordinal regression over K=100 equal-frequency time buckets trained with per-bucket BCE (regression AUC 0.75116); the execution agent learns Q(s,a|lambda_n) via the Bellman equation rather than regressing the observed (suboptimal-action-biased) RTG, and reweights its action loss by the sigmoid advantage between a and 1-a. The filtering agent is the heavy execution agent distilled into a 3-layer MLP that deliberately omits item-side features so it never invokes the ~10x more expensive recall/pre-rank/rank pipeline. In 14-day online A/B at 1B+ users STEPS lifted user active days +0.2843%, cut push-permission disablement -1.9089%, and cut compute -79.42% (filtering alone: -74.88% requests, -0.2465% NE); lambda_n is sampled from U(0,1) during training so the positive/negative trade-off is tunable online without retraining.
