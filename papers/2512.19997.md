## Summary

1.  Broken Access Control (BAC) vulnerabilities, a top API security risk, are difficult to detect using standard machine learning methods due to a lack of training data and the fact that BAC attacks often involve sequences of normal-looking requests.
2.  Existing data collection methods are impractical, as APIs often don't log composite traffic, and directly testing systems for BAC is often banned due to ethical and legal constraints.
3.  To overcome these challenges, the paper introduces BacAlarm, which generates realistic API traffic data to train a detector, resulting in significantly improved detection performance compared to current state-of-the-art methods.

## Technical note

BacAlarm detects Broken Access Control (BAC) violations in APIs, a task hampered by lack of labeled composite traffic and the fact that BAC attacks are sequences of individually-normal requests. It builds an API knowledge base from unlabeled logs and uses RAG-prompted LLMs to simulate benign and malicious composite API traffic, then trains an ensemble detector on bespoke sequential and API-syntax features (including transfer-entropy features). Evaluated on eight API-sets from two open-source systems with real CVEs, it beats invariant-based and learning-based SOTA by 21.2% F1 and 24.1% MCC. Ablations confirm every component (API info, hallucination elimination, sequence features) is necessary.
